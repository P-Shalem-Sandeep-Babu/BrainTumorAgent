======================================================================
BRAIN TUMOR AGENT: PROJECT EXPLANATION & DEFENSE GUIDE
======================================================================
Use this guide to explain your project architecture, models, and agents 
during your project defense or presentation.

----------------------------------------------------------------------
1. THE DEEP LEARNING MODEL
----------------------------------------------------------------------
* What model is used?
  We are using a Vision Transformer (ViT), specifically the 
  `google/vit-base-patch16-224` model loaded via HuggingFace.

* Where is it implemented?
  Located in: src/model/vit_model.py 

* Why use a Vision Transformer?
  Traditional image processing relies on Convolutional Neural Networks 
  (CNNs), which look at small, local pixel areas (edges, textures). 
  Vision Transformers cut the image into "patches" and use a mechanism 
  called 'Self-Attention'. This allows the model to look at a pixel in 
  one part of the brain and immediately understand its relationship to a 
  pixel on the opposite side. For medical imaging, where a tumor's 
  context within the entire brain structure is vital, this "global 
  understanding" makes ViT extremely powerful.

* What could have been used instead, and why didn't we?
  - Alternative: ResNet-50, VGG-16, or EfficientNet (CNNs).
  - Why rejected: CNNs are the industry standard and faster to train, 
    but they struggle with global context due to their localized receptive 
    fields. ViT leverages state-of-the-art NLP architecture adapted for 
    vision, making the project cutting-edge. Note: Because ViTs are 
    heavy, the code freezes the first 8 layers to optimize training speed 
    without losing accuracy.

----------------------------------------------------------------------
2. THE REINFORCEMENT LEARNING (RL) AGENT
----------------------------------------------------------------------
* What agents are used?
  1. Deep Q-Network (DQN): Set up as a clinical recommendation agent.
  2. Proximal Policy Optimization (PPO): Supported for continuous envs.

* Where are they implemented?
  Agents: src/agent/train_dqn.py and src/agent/train_agent.py
  Environments: src/environment/treatment_env.py

* Why use DQN for recommendations?
  RL is about decision-making. The DQN agent maps a medical condition 
  (classified by the ViT) to a clinical action. 
  - Action Space: 4 discrete choices ("Monitor", "Specialist", "Biopsy", "Emergency").
  - Why DQN: DQN is specifically designed to excel in environments with a 
    discrete number of choices. It calculates a "Q-value" for every 
    possible action and chooses the best one, making it perfect for 
    selecting a specific medical recommendation.

* What could have been used instead, and why didn't we?
  - Alternative 1 (Hardcoded Rules): Using simple `if/else` statements.
    Why rejected: Hardcoding is not Artificial Intelligence. By using an 
    RL agent, the system *learns* the correct policy through simulated 
    trial and error, proving the concept of an adaptive AI that could 
    learn from real hospital feedback.
  - Alternative 2 (A2C or SAC Agents):
    Why rejected: Soft Actor-Critic (SAC) is built for continuous actions 
    (like steering a car), which doesn't fit multiple-choice medical 
    recommendations. DQN is highly efficient for this discrete task.

3. MODEL TRAINING & OPTIMIZATION
----------------------------------------------------------------------
* How was the model trained?
  The model training (found in src/model/trainer.py) follows standard 
  industry best practices for deep learning:
  
  1. Data Split & Augmentation: Data is split into Training, Validation, 
     and Test sets. The training set uses Albumentations for data 
     augmentation (flipping, rotation, brightness adjustments) to prevent 
     the model from just memorizing the images.
  2. Loss Function: We use 'CrossEntropyLoss'. This is the standard loss 
     function for multi-class classification problems because it heavily 
     penalizes predictions that are confident but wrong.
  3. Optimizer: We use 'AdamW' (Adam with Weight Decay). AdamW is superior 
     to standard Adam or SGD because it properly decouples weight decay 
     from the learning rate, providing better regularization and helping 
     the ViT generalize better.
  4. Learning Rate Scheduler: We use 'ReduceLROnPlateau'. If the model 
     stops improving (plateaus) on the validation set, this scheduler 
     automatically reduces the learning rate to make finer adjustments 
     to the weights.
  5. Early Stopping: We monitor the validation loss. If it fails to 
     improve for a set number of epochs, training automatically stops. 
     This is the best approach to prevent "overfitting" (where the model 
     memorizes the training data but fails on new data).
  6. AMP (Automatic Mixed Precision): We utilize PyTorch AMP (float16) 
     during training. This allows the model to train twice as fast on 
     modern GPUs while using significantly less video memory.

4. TECH STACK DECISIONS
----------------------------------------------------------------------
* Why PyTorch over TensorFlow?
  PyTorch was chosen because it is the dominant framework in modern AI 
  research (especially for Transformers via HuggingFace). Its dynamic 
  computation graph allows for much easier debugging during model training.

* Why Streamlit for the Frontend?
  Streamlit allows rapid prototyping of data science and machine learning 
  applications purely in Python. It avoids the overhead of building a full 
  React/Node.js stack, ensuring the project focus remains on the AI model 
  architecture rather than web development boilerplates.

----------------------------------------------------------------------
5. LIMITATIONS & FUTURE SCOPE
----------------------------------------------------------------------
* What are the limitations of your current project? (CRUCIAL QUESTION)
  Evaluators almost always ask for limitations. Be honest:
  - Dataset Size: The model is trained on a standard MRI dataset. In a 
    real-world clinical setting, it would need to be trained on millions 
    of high-resolution DICOM images from multiple hospitals to prevent 
    dataset bias.
  - 2D vs 3D Scans: The ViT model processes 2D slices. Real MRI scans are 
    3D volumes. A future upgrade would be a 3D Vision Transformer.
  - Clinical Liability: The DQN agent is a proof-of-concept for decision 
    support. It cannot replace a human oncologist due to medical liability.

* Future Scope
  - Implement "Explainable AI" (XAI) such as Attention Rollout to highlight 
    the exact pixels the ViT used to make its decision.
  - Deploy as a microservice API that hospitals could integrate into their 
    existing PACS (Picture Archiving and Communication Systems).

EXECUTIVE SUMMARY PITCH
----------------------------------------------------------------------
"Instead of just building a standard CNN image classifier, I built a 
two-stage hybrid AI system. The first stage uses a Vision Transformer, 
a state-of-the-art attention-based model, to achieve high accuracy in 
tumor feature extraction by analyzing global image context. The second 
stage uses a Deep Q-Network reinforcement learning agent to act as a 
simulated clinician, learning the optimal treatment recommendation policy 
through a reward-based Markov Decision Process. The entire system was 
trained using best practices like AdamW optimization, Early Stopping, 
and Mixed Precision. This elevates the project from a simple classifier 
to an automated, robust decision-support agent."
